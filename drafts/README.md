# drafts/

本机运行 `python3 server.py` 后，这里的草稿会出现在网页左侧的原稿列表里（标记为 `drafts`）。

草稿按类型分到 `图文/` 和 `长文/` 两个文件夹，每篇草稿单独一个文件夹：

```
drafts/
  图文/
    我的标题/
      我的标题.md
      assets/
        配图.png
  长文/
    另一篇/
      另一篇.md
```

- `图文/` 里的草稿在网页里按图文卡片打开，`长文/` 里的按长文打开，原稿列表的“图文 / 长文”筛选也按这个分。直接放在 `drafts/` 下的草稿文件夹不会载入。
- 已关联 `drafts/` 的稿件点“转图文”或“转长文”时，会先写回一次，再把整个草稿文件夹（含 `assets/`）移到对应类型下，原位置不再保留，网页里的这篇跟着关联到新位置。目标文件夹重名时自动加 `-2`、`-3`。
- 文件夹里的 Markdown 优先认 `<文件夹名>.md`，其次 `index.md`，否则取文件夹里唯一的 `.md`。直接放在 `drafts/` 下的 `.md` 不会载入。
- 标题可以写在文件开头的 front matter 里，不写就用文件夹名：

  ```markdown
  ---
  title: 我的标题
  ---

  正文……
  ```

- 图片放在草稿自己的 `assets/` 里，正文用 `![](assets/图片.png)` 或 `![[图片.png]]` 引用。
- 实况图写成 `![封面](assets/封面.jpg "live:assets/视频.mov")`：括号里是封面图，引号里 `live:` 后面是原视频。
- 在网页里修改后，停笔约 1 秒会自动写回对应的 `.md`；网页里新加的图片、GIF 和实况视频按原文件存进这篇草稿的 `assets/`。
- 点“下载 → 保存到项目”时，会再检查一遍正文引用的文件，`assets/` 里被删掉的会重新存一份。
- 文件在别处更新后，刷新网页或点原稿列表顶部的同步按钮即可重新载入。
- 网页和文件两边都改过时，写回前会弹窗让你选：用网页内容覆盖文件，或改用文件里的内容。
- 在网页里点“下载 → 保存到项目”时，会按当前类型存进 `图文/` 或 `长文/`：已关联但类型不一致的先移过去；还不在 `drafts/` 里（或对应文件夹已被删掉）的，以标题新建一个草稿文件夹并关联上。`drafts/` 不存在时会自动创建。这个按钮只在本机运行 `server.py` 时出现。
- “下载 → 下载ZIP原稿”只下载 ZIP，不会写入 `drafts/`。
- 在网页里删除原稿不影响文件。双图并排、裁剪等网页排版在 Markdown 里没有对应写法，写回后会变成普通图片。
- 这个文件夹不会部署到 GitHub Pages，但提交到仓库后仍会公开显示在 GitHub 上。
